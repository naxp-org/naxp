naxp library APIs

naxp libraries are available in a number of languages with the following run-time functionality:

  • Parse. Parse a naxp pattern and, if successful, return an object representing the naxp.
  • Encode. Map text to its encoded value.
  • Decode. Map an encoded value back to (canonical) text.
  • Validate. Check whether text is valid for a naxp, among other checks.
  • Generate code for a specific naxp.

Tip If you want to implement a specific naxp without linking a library or paying a run-time cost, the code-gen page writes the functions for you.

C

A plain C interface over the C++17 library, for C programs and for any language that can call C.

Install

For builds not using CMake, copy the self-contained amalgamated source naxp.cpp plus naxp.h from the latest release, and link with the C++ driver (g++ or clang++), since the library behind the interface is C++. With CMake, fetch the library with FetchContent, declaring C++ as well as C so that CMake links the C++ runtime: 

project(your_project LANGUAGES C CXX)

include(FetchContent)
FetchContent_Declare(naxp
	GIT_REPOSITORY https://github.com/naxp-org/naxp.git
	SOURCE_SUBDIR src/cpp)
FetchContent_MakeAvailable(naxp)

target_link_libraries(your_target PRIVATE naxp::naxp)

Example

#include <naxp/naxp.h>

const char *pattern = "\\A\\A?\\9\\X? \\s!! \\9\\A\\A | GIR \\s!! 0AA";
naxp_error *error = NULL;
naxp *postcode = naxp_parse(pattern, strlen(pattern), &error);
char text[16];

naxp_max_encoded_value(postcode);  /* 1755842401 */
naxp_max_length(postcode);  /* 8 */
naxp_encode_cstr(postcode, "EC4M 8AD");  /* 278794572 */
naxp_encode_cstr(postcode, "EC4M8AD");  /* 278794572 (same as above) */
naxp_decode_cstr(postcode, 278794572, text, sizeof text);  /* true, text is "EC4M 8AD" */
naxp_canonical_form_cstr(postcode, "EC4M8AD", text, sizeof text);  /* true, text is "EC4M 8AD" */
naxp_accepts_cstr(postcode, "invalid");  /* false */
naxp_encode_cstr(postcode, "invalid");  /* 0 */

naxp_free(postcode);

C++

A C++17 library in the namespace logmu.

Install

For builds not using CMake, copy the self-contained amalgamated source naxp.cpp plus naxp.hpp from the latest release. With CMake, fetch the library with FetchContent: 

include(FetchContent)
FetchContent_Declare(naxp
	GIT_REPOSITORY https://github.com/naxp-org/naxp.git
	SOURCE_SUBDIR src/cpp)
FetchContent_MakeAvailable(naxp)

target_link_libraries(your_target PRIVATE naxp::naxp)

Example

#include <naxp/naxp.hpp>

const auto postcode = logmu::naxp::parse(R"(\A\A?\9\X? \s!! \9\A\A | GIR \s!! 0AA)");

postcode.max_encoded_value();  // 1755842401
postcode.max_length();  // 8
postcode.encode("EC4M 8AD");  // 278794572
postcode.encode("EC4M8AD");  // 278794572 (same as above)
postcode.decode(278794572);  // "EC4M 8AD" (canonical form)
*postcode.canonical_form("EC4M8AD");  // "EC4M 8AD" (canonical form)
postcode.accepts("invalid");  // false
postcode.encode("invalid");  // 0

C#

.NET library and source generator.

The source generator compiles a naxp at build time (just like C# does for regexes). The generated code needs C# 7.3 or later, and the source generator needs the .NET 8 SDK or Visual Studio 2022 17.8 or later.

Install

dotnet add package naxp

The NuGet package targets .NET 8 and .NET Standard 2.0, which means it runs on .NET Framework.

Example

using LogMu;

var postcode = Naxp.Parse(@"\A\A?\9\X? \s!! \9\A\A | GIR \s!! 0AA");

postcode.MaxEncodedValue;  // 1755842401
postcode.MaxLength;  // 8
postcode.Encode("EC4M 8AD");  // 278794572
postcode.Encode("EC4M8AD");  // 278794572 (same as above)
postcode.Decode(278794572);  // "EC4M 8AD" (canonical form)
postcode.GetCanonicalForm("EC4M8AD");  // "EC4M 8AD" (canonical form)
postcode.Accepts("invalid");  // false
postcode.Encode("invalid");  // 0

JavaScript

Plain JavaScript modules, with TypeScript declarations, for Node 18 or later and for the browser.

This is the library that runs the interactive pages on this website.

Install

npm install @naxp/naxp

The package on npm has zero dependencies and no build step.

Example

import { Naxp } from '@naxp/naxp';

const postcode = Naxp.parse('\\A\\A?\\9\\X? \\s!! \\9\\A\\A | GIR \\s!! 0AA');

postcode.maxEncodedValue;  // 1755842401n
postcode.maxLength;  // 8
postcode.encode('EC4M 8AD');  // 278794572n
postcode.encode('EC4M8AD');  // 278794572n (same as above)
postcode.decode(278794572n);  // 'EC4M 8AD' (canonical form)
postcode.getCanonicalForm('EC4M8AD');  // 'EC4M 8AD' (canonical form)
postcode.accepts('invalid');  // false
postcode.encode('invalid');  // 0n

Parsing errors

When parsing a naxp pattern fails, the error is reported as (a) an error code, (b) an informative error message, and (c) the zero-based offset and (d) the length of the part of the pattern in error.

For example, parsing A{2-5} reports:

Error code"NAXP1002"
Error message"The counts of an interval are separated by ',', not '-'. Write 'A{2,5}'."
Offset3
Length1

All error codes are listed here.

Create a new implementation

If you want to write an implementation in a language not already covered then:

  1. Please open an issue on GitHub so that work is not duplicated.
  2. Take a look at the existing implementations above to understand how they work.
  3. Test your implementation against the conformance data, a JSON file per specification version that is generated from the specification itself rather than from any implementation, so an implementation cannot define its own truth by passing it. It comprises
    • well-formed naxps, each with its value count and a set of texts with their encoded values and canonical forms (every accepted string, for the smaller cases),
    • invalid text for those naxps, and
    • invalid naxps, each tagged with the rule it breaks.

    Counts and encoded values are written as decimal strings, because they legitimately reach 264 − 1 and most JSON parsers read a number into a double.
