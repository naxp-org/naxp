naxp error codes

A naxp that is refused is refused with a code, such as NAXP1031. The code names the fault, so a log or a bug report can identify it without quoting the words, and the words can be improved without breaking anything that reads the code.

There are two families.

  • NAXP1001 and upwards are faults in the naxp itself. Every implementation reports these, and reports the same fault under the same code: a naxp refused by one implementation is refused by all of them.
  • NAXP0001 to NAXP0010 are faults only a build can see, raised by the C# source generator about the [Naxp] attribute and the type carrying it. They are specific to that package.

Tip Each code below is linkable, as /codes/#naxp1031. In Visual Studio the code in the Error List links here directly.

Faults in a naxp

The Rule column says what the fault offends against: Syntax for a pattern that does not parse, and W1 to W6 for a pattern that parses but is not well formed, as the specification defines them. A few are limits this implementation imposes rather than rules of the language.

Where a message shows {0}, the text at fault is written there.

Faults the C# generator reports

These come from the source generator in the naxp package for .NET, which compiles a naxp at build time. They are about the attribute and the type it sits on rather than about the naxp, which is why they are numbered apart. Each is an error: every one of them stops a naxp being generated, and generated code that silently went missing would fail later and further away.
